# 每日签到

入口：用户侧栏「每日签到」(`/checkin`)。普通模式开放，简易模式在前后端均禁用。

## 规则 v1

- 北京时间每日 00:00 重置，每人每天领取一次，含当日的连续签到天数用于本次评分。
- 周指标统计最近 7 个北京时间自然日：今天及前 6 天，截至领取时。不是周一统一清零。
- 调用活跃：每天有 `actual_cost > 0` 的调用计一个活跃日，余额与订阅调用均计入；最高 7 天，按 `40 × 天数 / 7` 评分。
- 连续签到：含当天，断签重计，最高 7 天，按 `40 × 天数 / 7` 评分。页面的「已连续签到」只显示实际已签到天数。
- 消费：周内余额消费 (`billing_type = 0`) 的 `actual_cost` 总和；$0 / $1 / $5 / $10 / $20 分别得 0 / 3 / 8 / 12 / 15 分，区间线性计算，封顶 15 分。
- 充值：周内有成功完成的余额订单，且没有全额退款，得 5 分；赠送、管理员调账、订阅购买不计入。未完成的退款申请不视为已退款。

| 奖励 | 0 分概率 | 100 分概率 |
| --- | --- | --- |
| $0.01 | 65% | 25% |
| $0.03 | 25% | 30% |
| $0.10 | 8% | 30% |
| $0.50 | 1.5% | 12% |
| $1.00 | 0.5% | 3% |

总分在两个端点之间线性插值。首日签到本身获得 40/7 分，因此 0 分是概率公式端点，并非实际领取的最低分。使用安全随机数和百万分之一整数权重抽奖，金额用整数美分记录。

## 接口和一致性

- `GET /api/v1/user/checkin`：返回北京时间日期、下次重置时刻、领取状态、评分与概率、最近 30 次签到记录。已领取时返回当次保存的快照。
- `POST /api/v1/user/checkin`：必须提交页面人机验证凭据（Turnstile/阿里云用 `turnstile_token`，腾讯用 `tencent_captcha_ticket` 和 `tencent_captcha_randstr`）。用户身份来自当前登录会话，不接受客户端指定用户、金额、概率或验证指纹。返回同样的状态结构。
- 签到独立强制验证，不随登录验证码的可选策略放行。复用后台已启用的腾讯、阿里云或 Turnstile 服务；未启用、配置冲突、验证失败或服务异常时停止发奖。开启功能前须在后台配置其中一家并设置本站域名。
- 只保存已验证凭据的 SHA-256 指纹，随领取事务写入唯一索引，阻止同一凭据在不同账户或日期重复发奖。腾讯按 ticket 标识；JSON 形式的阿里云参数规范化后计算指纹。原始凭据不落库。
- 数据库事务先锁用户，再计算、保存签到记录、增加余额、写入 `checkin_balance` 历史。`(user_id, checkin_date)` 唯一约束作为额外保护；已领取的请求直接返回原结果。
- 奖励不更新充值累计，不触发充值返利。事务提交后清理鉴权和余额缓存；重复领取也执行缓存清理。
- 用户可通过 GET 刷新已经提交但响应丢失的结果，无需重做验证。再次 POST 需新的有效验证凭据；成功验证后仍返回当天原奖项。前端先获得服务端结果，再播放对应奖项动画；动画不是入账前提。
- 新增迁移 `250_daily_checkins.sql` 和 `251_daily_checkin_captcha.sql`，随服务启动执行。历史签到指纹允许为空，新领取由服务强制要求有效指纹。规则固定为 v1，修改未来规则时应提升快照版本，已发奖励不重新计算。
- 网页仍通过 API 提交；保护目标是阻止仅凭登录令牌直接领取，不承诺识别所有浏览器自动化或验证码代解行为。

## 验证

- 后端测试覆盖消费阶梯、全部随机票号分布、概率上限、北京时间午夜、断签、首次发奖/重试、流水失败回滚、禁用账号和简易模式。
- 前端测试覆盖重复点击、恢复结果、网络失败重试、余额刷新失败、跨午夜和计时器清理。
- 浏览器使用模拟接口检查桌面、320px/390px 手机、深色模式与刷新恢复，不向真实账户发放奖励。
- 上线前应在测试 PostgreSQL 实例执行迁移，并发请求同一账号，确认只有一条签到、一条赠送流水及一次余额增加；当前本地验证未连接真实数据库。
